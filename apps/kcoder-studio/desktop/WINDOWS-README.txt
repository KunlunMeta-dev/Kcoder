KCoder Studio — Windows 桌面客户端

本安装包包含桌面界面、本机 Gateway、Windows KCoder 运行时和进程管理组件。
启动“ KCoder Studio ”即可使用，不需要单独启动浏览器或安装 Node.js。

命令行（CLI）：
  同一个安装包同时安装 KCoder Studio 和 kcoder 命令行版本，无需另装 CLI。
  安装后重新打开 PowerShell / CMD，执行 kcoder --version 或直接执行 kcoder。
  Windows Terminal 如未识别命令，请完全退出后重新打开；已打开的终端不会自动更新 PATH。
  CLI 与 Studio 共用安装目录内 resources\bin\kcoder.exe，随同升级和卸载。
  默认只修改当前用户 PATH；若明确选择“所有用户”安装，则注册系统 PATH。
  不会删除已有独立 CLI，也不会覆盖它们的配置。
  如存在其它 kcoder 命令，可运行 where.exe kcoder 检查实际使用版本。
  卸载保留用户配置、凭据和历史；预先手工添加的 PATH 条目不由安装器移除。

默认技能：
  首次正常启动自动安装 17 个随包技能和更新后的 kcoder-settings 到当前配置目录 skills\.builtin。
  CLI 与 Studio 共用，用户自定义的同名技能优先；安装不会自动运行技能脚本或安装外部依赖。
  原有 14 个 Superpowers 技能仍包含在程序中，通过项目 SpecInit 安装到 .kcoder\skills。
  字体、模板、脚本及原有许可文件完整保留。

本机项目：
  默认目标“当前计算机”在 Windows 本机执行工具、终端和文件操作。
  在设置中配置模型 Provider 与凭据，再选择本机工作区创建任务。
  同一 Provider 可以添加多个模型；连接和密钥共享，模型的上下文限制与能力独立保存。
  使用 Git 仓库前请安装 Git for Windows；额外工具仍需在目标机器安装。

远程项目（SSH）：
  1. Windows 安装并启用 OpenSSH 客户端，配置 SSH key 或 ssh-agent。
  2. 先在终端使用 ssh 用户名@主机 成功登录，检查并确认主机指纹。
  3. 远程 Linux 机器安装兼容版本的 kcoder，配置该机器自己的模型凭据。
  4. 在 Studio 设置 → 运行目标中添加 SSH 主机、用户、端口、远程工作区。
  5. 测试连接后保存，在对应远程目标下创建任务。
  当前 SSH 入口使用非交互密钥认证，不会弹出 SSH 密码输入框。
  Linux 工作区使用 /data/project 等 POSIX 绝对路径；不要求远端打开图形客户端。

边界：
  本机目标的文件、终端、插件和模型配置属于 Windows；远程目标的这些数据属于远程机器。
  添加运行目标不会自动复制项目、会话、API Key 或 SSH 私钥。
  HTTP 网关薄客户端与 SSH 运行目标不是同一种连接；本完整包的目标管理入口使用本机/SSH。
  断开客户端不代表远程任务可以无限后台保活，具体取决于服务端的连接生命周期。

安全：
  安装包不包含个人服务器地址、登录口令、API Key 或私钥。
  当前包未进行商业代码签名，Windows 可能显示未知发布者提示。
  卸载默认保留用户配置和历史；请勿把该目录当作安装文件删除。

定时任务：
  菜单“自动化 → 定时任务”或侧栏“自动化”可以管理绑定到已有会话的任务。
  支持一次性、间隔和高级 UTC Cron。创建时需明确勾选执行同意。
  任务保存在执行目标的工作区，遵循该会话的模型和权限，忙碌时排队。
  当前版本需要客户端和会话保持连接；关闭客户端后不保证执行。
  结果和可能出现的工具审批，在关联会话中查看。
  安装新版后请退出旧客户端再启动，远端 KCoder 也必须升级并重新建立 SSH 连接。
