What is KCoder?

KCoder is an auditable, extensible, locally runnable engineering agent runtime — not a wrapper that just prints model output. Conversation, tool calling, permission controls, SQLite long-term memory, Skills, slash commands, history search, sub-agents, spec workflows, MCP servers, plugins, and scheduled tasks all ship in one statically linked binary.

The implementation is organized as a Cargo workspace of 19 crates with clearly separated responsibilities — types, API, engine, tools, memory, permissions, skills, specs, REPL, CLI, workflow, process supervisor — composing a complete agent with no hidden state. The machine-readable app-server and Gateway back KCoder Studio on desktop, Web, and mobile.

Provider-agnostic

Anthropic, OpenAI-compatible endpoints (Kimi, MiniMax), KunlunMeta, local vLLM/SGLang, Gemini, and Grok — all unified behind the Provider trait.

Spec-driven

Behavior changes are proposed as delta specs under .kcoder/specs/, validated against tests and drift checks, then archived with evidence.

Multi-surface

Interactive TUI, headless one-shot prompts, JSON event streams, a tmux-backed daemon, and the JSON-RPC app-server powering Studio clients.

Engineering discipline

TDD guard, permission modes, Landlock sandboxing on Linux plus a Windows sandbox, hook systems, audit logs, and bounded tool outputs.

Core Features

A refined coding-agent capability surface built on Rust reliability, explicit permissions, and auditable workflows.

🛡️

Permissions & sandbox

Five modes: ask, auto, accept-edits, dont-ask, bypass; per-tool TUI dialogs with persisted allow/deny lists; Landlock sandboxing on Linux, a Windows sandbox, and bash risk classification via tree-sitter decomposition.

🧠

SQLite long-term memory

Structured facts with an FTS5 retrieval layer, model and deterministic observers, a privacy policy, validation gates, and /memories status — injected automatically into future system prompts.

🎯

Skills & SkillStore

Markdown skills with YAML frontmatter from project, user, and bundled sources; a transactional SkillStore with canonical SHA-256 revisions, CAS updates, background curation, and lifecycle governance.

🔁

Spec-driven development

Delta specs under .kcoder/specs/ with two schemas, fingerprinted drift detection, validation gates tied to cargo test, parallel drafting, and archival with verification records.

🔌

MCP & plugins

MCP over stdio, legacy SSE, and Streamable HTTP with full OAuth authorization (RFC 9728 resource metadata, dynamic client registration); plugins contribute hooks and MCP servers through manifest formats with a trust gate; plugin marketplaces are first-class.

🤖

Sub-agents & orchestration

spawn_agent / explore_agent parallel dispatch, agent fleets, targeted steering and stopping of background sub-agents, /orchestrate session orchestration, and MoA (mixture of agents) plan synthesis.

🏁

Goal Pro

/goal long objectives with /goal-pro strict verification: verifier rounds, test scoping, escalation rungs, and durable goal state that survives restarts.

⏰

Scheduled tasks & workflows

Cron-style scheduled tasks (at / interval / cron presets with UTC compilation), a tmux-backed background daemon (kcoder daemon), and a JavaScript workflow runtime exposed through the Workflow tool.

🖥️

KCoder Studio

Desktop (Electron + Tauri), Web, and mobile clients over the Gateway and JSON-RPC app-server: workbench, account isolation, SSH/remote targets, file menus, terminals, usage dashboards, and scheduled-task management.

Quick Start

From clone to first answer in under a minute.

  1. 1 · Install

    # Local release installer (builds from the checkout)
$ scripts/install/installers/cli-release.sh
$ export PATH="$HOME/.local/bin:$PATH"

# Or build directly
$ cargo build --release

    The installer runs cargo build --release --locked locally — no cloud CI, no sudo, no credential imports.

  2. 2 · Configure a provider

    # Interactive credential login
$ kcoder auth login --provider kunlunmeta

# Or export standard environment variables
$ export ANTHROPIC_API_KEY=sk-...
$ export OPENAI_API_KEY=...

  3. 3 · Ask or launch the TUI

    # Headless one-shot question
$ kcoder "Summarize crates/kcoder_engine/src/lib.rs"

# Auto-accept file edits and run a multi-step task
$ kcoder --permission-mode accept-edits \
    "Refactor error handling in kcoder_cli"

# Launch the interactive TUI
$ kcoder

    TUI shortcuts: Enter send · Ctrl+C / Esc quit · Ctrl+R history search · / slash commands.

Model Providers

Every provider hides behind the same Provider trait. Switch via CLI flags, settings, or environment variables — no code changes.

KunlunMeta (default)

The built-in default profile (Anthropic Messages protocol). Endpoint and model are user-configurable.

kcoder auth login --provider kunlunmeta
kcoder --provider kunlunmeta "hi"

Override with KUNLUNMETA_BASE_URL and KUNLUNMETA_BASE_MODEL.

Anthropic

An Anthropic-compatible provider using official model IDs and the Messages protocol.

kcoder --provider anthropic \
       --api-key sk-... \
       --model <anthropic-model-id> \
       "hi"

Point --base-url at a self-hosted Anthropic-compatible endpoint.

OpenAI-compatible (Kimi, MiniMax…)

Chat Completions and Responses protocols against any compatible endpoint.

kcoder --provider openai \
       --openai-base-url https://api.kimi.com/coding/v1 \
       --openai-api-key sk-... \
       --model kimi-for-coding/k2p6 \
       "hi"

Local vLLM / SGLang

Local providers don't require an API key — ideal for vLLM, SGLang, or any Chat Completions-compatible service.

kcoder --provider local \
       --local-base-url "http://127.0.0.1:8000/v1" \
       --model "your-model" \
       "hi"

--tool-profile auto uses the smaller core tool set; for pure chat testing use --tool-profile none.

Gemini & Grok

Native clients: Gemini streams via streamGenerateContent; Grok uses xAI's OpenAI-compatible endpoint. Enabled with KCODER_USE_GEMINI=1 or KCODER_USE_GROK=1.

Built-in Tools

Tools implement the Tool trait in kcoder_tools and register with role-scoped registries (core, orchestrator, worker). Every tool honors the active permission mode and bounded-output rules.

Project Status

What has shipped, what's in progress, and the known boundaries.

✅ Shipped

  • Six provider families behind one Provider trait with typed transport-failure recovery
  • Streaming responses, token-level TUI rendering, layered context compaction
  • 40+ built-in tools across role-scoped registries with bounded outputs
  • Five permission modes, Landlock + Windows sandboxing, audit logging
  • SQLite + FTS5 structured memory with observers and privacy policy
  • Transactional SkillStore with curation and lifecycle governance
  • Spec-driven workflow with two schemas and drift detection
  • Plugins, marketplaces, lifecycle hooks with trust gates
  • MCP over stdio / SSE / Streamable HTTP with OAuth authorization
  • Sub-agents, agent fleets, orchestration, MoA, Goal Pro
  • Scheduled tasks, tmux daemon, JS workflow runtime, LSP (pyright)
  • KCoder Studio: desktop, Web, and mobile clients with account isolation

🚧 Known boundaries

  • LSP integration currently covers Python (pyright); more languages planned
  • Vector retrieval for memory is on hold; SQLite + FTS5 is the retrieval layer
  • apply_patch is not built in; write / edit cover file modification
  • Web tools depend on real network reachability and proxy policy
  • Windows is covered by conditional compilation and CI contracts; deepest test coverage is Linux/macOS

FAQ

Where are configuration files stored?

Settings: ~/.config/kcoder/settings.json; memory: the config sub-directory (SQLite + FTS5); user-level skills: ~/.config/kcoder/skills/; project-level skills: .kcoder/skills/; project instructions: KCODER.md or AGENTS.md (discovered upward from cwd).

How do I avoid permission dialogs in unattended scripts?

Use --permission-mode bypass — it allows every tool without prompting. Combined with headless mode it works directly in CI.

Does /model switch providers?

No — /model only switches the model identifier. To switch providers, use the --provider CLI flag, layered settings, or environment variables such as KCODER_USE_OPENAI=1.

Can I use KCoder from other applications?

Yes — kcoder app-server exposes a JSON-RPC interface over stdio used by KCoder Studio's desktop, Web, and mobile clients; headless mode emits JSON events for scripting.

What are the key dependencies?

Core dependencies include tokio (async runtime), reqwest + reqwest-eventsource (HTTP/SSE), ratatui + crossterm (TUI), rusqlite (SQLite memory), tree-sitter (bash risk classification), rquickjs (workflow runtime), serde / serde_json (serialization), syntect + pulldown-cmark (rendering), tracing (logging), plus anyhow / thiserror. Edition 2024, minimum Rust 1.95.

How is the project tested?

A workspace-wide Rust test suite, renderer/Node suites for Studio, a project-level test matrix (tests/matrix.toml) spanning TUI, harness, e2e, and real-model tiers, plus contract tests that guard packaging, secrets, and documentation. CI runs the PR tier on every push.
