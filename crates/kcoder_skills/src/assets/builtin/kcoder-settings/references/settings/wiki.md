# Wiki Configuration and Recovery

Read only for Wiki availability, organization models, import limits or failed jobs. Use the selected execution target and account.

## Wiki Availability and Target Scope

Wiki has independent `knowledge.retrieval_enabled` and `knowledge.organization_enabled` boolean overrides. Both default off. When absent, each inherits legacy `knowledge.enabled`; explicit individual values take precedence. Prefer Studio **Wiki → target selector → Retrieval / Organization**. For conversational changes, use Config on the specific key the user requested. A legacy Config write to `knowledge.enabled` sets both; do not use that shorthand when the user requested only retrieval or only organization. Never enable either merely to obtain a missing tool. Neither `tui.alternate_screen`, permissions, nor the Provider address controls these switches.

Retrieval alone mounts `Wiki`; organization alone mounts `WikiManage`, including bounded maintenance reads needed for explicit organization requests. Do not use maintenance reads to bypass disabled retrieval for ordinary question answering. Turning retrieval off does not pause organization. Turning organization off pauses queued/running jobs while retrieval can stay on; re-enabling does not resume those jobs automatically. Eligible running engines refresh each tool independently without restart; restricted registries and `tools.profile: none` remain restricted. Always inspect the actual registry. Neither switch enables implicit conversation ingestion or mandatory retrieval every turn.

The `Wiki` tool supports read actions `libraries`, `pages`, `sources`, `source`, `search`, `read`, `references`, and `citation`. Reuse returned library IDs, revision IDs, and cursors; pin the returned revision when continuing a long page. For explicit maintenance requests, `WikiManage` provides `create`, `set_default`, `rename`, `import_text`, `allocate_ids`, `propose_pages`, `jobs`, and `pause`, plus bounded `find_pages`, `read_page`, `sources`, `source`, and `citation` for explicit maintenance. Import saves evidence; it does not by itself organize pages. Read the original chunks and supply exact citations when proposing generated pages. Reuse idempotency keys only for the same payload. A human-edit conflict does not commit or queue the proposal; direct the user to Studio review/edit instead of inventing a confirmation parameter. Studio supports human edits, history, restore, and review decisions. Its uploads accept up to 10 `.txt`/`.md`/`.html`/`.htm`/`.pdf`/`.docx`/`.xlsx`/`.pptx` documents and PNG/JPEG/WebP images, documents at most 32 MiB, images at most 10 MiB and the batch at most 128 MiB; originals and PDF page references are preserved. HTML import requires knowledgeHtmlV1 on the target, extracts offline text, excludes scripts/hidden content and never fetches external assets. HTML supports BOM UTF-16 and declared encodings such as GBK. Text and Office XML support UTF-8 or BOM-marked UTF-16. Excel reads stored dates/booleans and cached formula results without recalculation. Original images can be previewed and original files downloaded on targets advertising knowledgeOriginalFilesV1. Wiki output is bounded to 1,048,576 tokens, 4 MiB response text and 1 MiB per page; actual requests also honor the selected model output limit and remaining context. Raising Wiki limits cannot raise a model capability limit. If Wiki still truncates, inspect the effective max_tokens and its source, not just providers.<id>.models.<model>.max_output_tokens: an explicit flat max_tokens can override the model limit. Confirm the intended model limit and use the target configuration boundary to remove a stale override (CLI: kcoder config unset max_tokens --scope user), after backing up the target settings; do not silently remove intentional project/CLI overrides or disable reasoning. Citation mismatches receive up to two model repair calls against exact immutable source chunks, subject to the shared three-repair allowance; unresolved quotes still fail. Never normalize fabricated quotes or bypass evidence checks. Automatic Wiki workers may select private host-offered citation refs, which expand exact immutable source spans before evidence validation; this does not change WikiManage public literal citation fields. Do not invent a ref argument for public tools, infer a ref, or treat a valid source span as proof of every surrounding claim. On supporting source builds, `source_support` checks facts and applicable scope separately from quotation repair. Required source-support checks use the global model-call budget independently of the three-repair allowance; successful validation is not an independent guarantee of truth. Automatic new topic summaries have bounded output, while complete existing page updates keep their own allowance within the effective model limit. New automatic workers bind the purpose agenda and full selected-source inventory to the source revision, then verify required unit placements against actual topic-page lines and exact citations. Missing coverage permits an organization_repair complement only within its remaining repair allowance and the global model-call budget, while reserving the required final support check. This does not increase the three-repair limit. Validated intermediate results are reused after resume; do not bypass stale recipe, source, lease or body bindings. Source-only output, unestablished organization coverage, unsupported claims, or uncertainty require review; preserved raw text and a model complete vote are not proof of complete organization. Automatic worker metadata supports host-derived inverse links and explicitly selected whole-page ranges; these are private output forms, not new WikiManage parameters. A correctable owned plan or proof may receive one metadata-only correction within the existing allowance. Foreign source, unit, aspect and citation identities remain errors. Pending review must retain a real private candidate; never suggest editing the database or bypassing validation to make it completed. Dense source paragraphs/table rows and changed page lines may be grouped into complete adjacent ranges to fit the existing review budget; no tail, heading, header or qualifier is discarded. Every constituent assertion still needs support. The entire literal purpose is retained, so formatting/negative constraints are not invented factual topics. Titles, author names, years and versions require supplied-source or retained-citation evidence. A truncated metadata repair must be diagnosed against its actual stage allowance and effective model limit; do not assume raising the global ceiling repairs it. Do not approve review merely to make a job show completed, raise limits to bypass evidence checks, or treat the 1 MiB storage limit as a promise that every model response fits. PDFs need extractable text, with no automatic OCR. Conversational `import_text` is limited to 256 KiB. Studio also previews and imports the selected target folder’s immediate supported files (10 files / 128 MiB; no hidden files or recursive scan). TUI `/wiki` (alias `/knowledge`) reports availability; `/wiki on|off` submits a visible ordinary Config request for both switches, rather than claiming immediate success.

For SSH, inspect the server's configuration and account, not the Windows local profile. The target needs `knowledgeCatalogV1` and, for organization, `knowledgeIngestV1`. Wiki uses its existing model credentials; no embedding or reranking model is required. Shared compatibility-mode profiles share data. Supported Unix SSH/account targets use an independent target-side worker and survive accidental connection loss; managed accounts also need an updated account launcher. Local desktop jobs remain tied to their app-server process and may need resume after restart. Explicit account sign-out pauses jobs before disconnecting; disabling organization and archiving a library also pause work. Re-enabling/restoring does not resume paused jobs automatically. A changed processing recipe can reject resume and should be reported, not bypassed by editing the database. New workers show stage progress and retain validated intermediate results; incomplete JSON is not published. Studio provides archive/restore, source/page search, index rebuild, and legacy `.kwiki` migration up to 64 MiB. New capable targets also transfer streamed collections up to 1 GiB in parts of at most 96 MiB; keep the manifest and every listed part together. Browser download initiation is not proof that all parts were saved. Cancellation or incomplete/corrupt imports preserve the previous library. Migration keeps originals, all page revisions, and human-edit markers; it excludes tasks, identity, and credentials. Import uses the destination target account. Do not invent maintenance actions beyond the actual `WikiManage` schema or treat an imported archive as permission to execute tasks.

Governed account Wiki reads and job metadata require current read permission; existing WikiManage mutations and pause require read plus write. Create requires write and returns a creation receipt containing its server ID and the submitted metadata, rather than exposing an existing library's revision or archive state; read full metadata through a separately authorized view. Enabling Wiki, approving one tool call, or allowing a model/budget does not grant either permission. Same-profile old data remains read-only; do not migrate its owner to make a write succeed. `WIKI_WRITE_RESULT_NEEDS_RECONCILIATION` means the original write may already have committed while its current authority changed. Do not replay it as though nothing happened. Report the uncertainty, preserve the original request key and expected revision, and reconcile the actual library/job state through an authorized target view after access is restored.


## Wiki Stages and Resume

Wiki retrieval and automatic organization have independent switches on the selected target. Disabling organization pauses scheduling without disabling retrieval. New jobs on current targets persist source analysis, topic planning and individual topic candidates; Studio displays the actual stage and known topic counts. Expand details for diagnostics rather than interpreting elapsed time as percentage complete.

For a failed or paused job, use its stage-specific Continue action to resume the same job. Completed, still-valid stage artifacts are reused; failed, missing or invalidated work is repeated. A complete received response is private input to parsing and verification, not proof that a knowledge page is ready. Truncated responses cannot be reused as complete output. Page edits invalidate dependent candidates; source revisions, purpose and frozen model configuration remain part of the recovery identity. Do not promise reuse after changing those inputs or erase the Wiki to fix one failed topic. Legacy jobs keep their previous checkpoint recovery format.

Local and remote workers admit two jobs concurrently, coordinating automatic page merges within each library. Waiting for that merge slot is a real stage, not a dead model connection. Normal source-support verification uses the global model-call budget independently of the three-repair allowance; missing evidence and unresolved coverage still require review. Increasing output limits does not override factual checks or a model's actual capacity. Inspect target build, source revision, stage error and frozen job model settings before recommending a restart or changing credentials.


A Wiki job marked for review may have no complete candidate on older targets. Current targets expose `reviewAvailable:false` for that state and permit Continue on the same job; do not call approval on an empty checkpoint or delete the source. Ordinary model `notes`/`warnings` are advisory, while explicit `reviewNotes`/`unresolvedIssues` remain blocking. Accepted wire variations and unique whitespace-only quote restoration do not replace the final source and revision checks. These rules apply to every imported format after extraction, including images, text, PDF, Office and HTML.
