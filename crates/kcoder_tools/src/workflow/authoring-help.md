Validate required field types; do not hide missing data with empty defaults or boolean coercion. Build multiline command text from lines joined by a real newline, avoiding double-escaped strings. A resultCheck must assert required values, types, lengths and ID correspondence; missing preview entries or workflowError cannot automatically count as success. An intentional negative test must assert the exact expected failure and that unintended effects did not occur. Valid JSON that violates outputSchema is not repaired by a model. If a provider corrupts nested numeric/boolean/array arguments, use node_json, nodes_json, input_schema_json or definition_json containing valid JSON text instead of the corresponding object field; never supply both. These text alternatives are parsed losslessly and receive identical validation/permissions. ## Recovering a saved workflow

For a failed or interrupted run, prefer `Workflow({resume: run_id})` in its original session. New-format runs preserve every successful node checkpoint, not just Agent replies. A saved definition change requires a new run: use `Workflow({definition_id, version, reuse_from_run: old_run_id})` to reuse the dependency-closed successful portion of that same definition. Omit args/args_json to inherit the source inputs. Unchanged node bodies are reusable only when all upstream semantics, input values and runtime configuration still match; changed nodes and affected descendants rerun. Canvas positions, display titles and node list order are presentation only. Result checks run again on reused outputs. Keep source history immutable, inspect unknown effects before retrying, and never claim exactly-once external behavior. Historical runs without complete checkpoints return `workflow_checkpoint_unavailable`; explain the limitation rather than claiming reuse or silently starting a fresh run.
